# Design: Canonical minimal-DI example (celery rollout)

## Summary

Ship a canonical, runnable example in `modern-di-celery`: a minimal
`examples/` app wiring one `Settings` (APP scope) and one `GreetingService`
(REQUEST scope) into a task via the real `@inject` + `FromDI` idiom, an
in-memory/eager smoke test that proves it runs, and the README
`Usage example:` line. This follows the locked pattern from the
[faststream pilot](https://github.com/modern-python/modern-di-faststream/blob/main/planning/changes/2026-07-24.01-canonical-example-onramp.md),
adapted to celery's `@inject`/`FromDI`/`DITask` idiom.

## Motivation

The [blessed-ready on-ramp audit](https://github.com/modern-python/modern-di/blob/main/planning/audits/2026-07-22-blessed-ready-onramp-report.md)
found most integrations at D2=1 (a complete inline README example but no
dedicated, linked canonical example) / D6=1 (no `Usage example:` link).
faststream piloted the fix; this change rolls the same shape to
`modern-di-celery`.

## Design

**The example** — `examples/app.py` (+ `examples/__init__.py`): the smallest
runnable celery app that demonstrates the recommended wiring, matching the
README snippet's shape but as a complete program:

- `Settings` — `providers.Factory(scope=Scope.APP, creator=Settings)`.
- `GreetingService` — `providers.Factory(scope=Scope.REQUEST, ...)`, depends on
  `Settings` by type (auto-injected).
- one `@app.task` + `@inject` task taking the service via
  `typing.Annotated[GreetingService, FromDI(Dependencies.service)]`, wired by
  `setup_di(app, container)` on a `Celery` app. The `Celery(...)` app uses
  `broker="memory://", backend="cache+memory://"` — the same in-process,
  no-extra-dependency transport `tests/conftest.py`'s `app` fixture already
  uses (a real broker string like `redis://localhost` was tried first and
  rejected: `apply_async` resolves the transport class — even under
  `task_always_eager` — which raises `AttributeError` because the optional
  `redis` package isn't a project dependency). A header comment states how to
  point the example at a real broker/backend for production use.

**Smoke test** — `tests/test_example.py`: imports the example's
`app`/`container`/`greet`, and using the repo's existing in-memory/eager idiom
(`task_always_eager` + `task_store_eager_result` + explicit `container.open()`
— the same three lines `tests/conftest.py`'s `app` fixture already performs,
since `worker_process_init` never fires under eager execution) calls
`greet.delay("world").get()` and asserts the real greeting
(`"Hello, world!"`). This proves the example runs with no infra and keeps it
from rotting.

One extra line was required beyond the conftest three: `app.set_current()`.
`@inject` resolves its container via celery's thread-local `current_app`
proxy, which every `Celery(...)` constructed with the (default)
`set_as_current=True` silently overwrites. Because `examples/app.py`'s `app`
is built once at import time, by the time the full suite reaches
`test_example.py` other test modules' fixtures have each constructed their own
`Celery(...)` and stolen `current_app`. `app.set_current()` reclaims it —
harmless in real deployments, which only ever construct one `Celery` app.

**Coverage** — none excluded. The smoke test executes `examples/app.py` end to
end (import wires the app/container/task; the `.get()` call runs the task body
and `GreetingService.greet`), so it covers the example to **100%** under the
repo's existing `--cov-fail-under=100` gate.

**README** — insert `Usage example: [examples/](./examples)` directly under
the `Full guide` line, matching faststream's placement.

No `modern_di_celery/` source changes, so no `architecture/` promotion — this
adds documentation-grade example + test, not a capability change.

## Non-goals

- The remaining rollout repos and core `writing-integrations.md`
  codification — separate, independent changes.
- A realistic/DB-backed starter — minimal DI demo only.
- New runtime dependencies — the example uses only `celery` + `modern-di`,
  already present.
- Editing the inline README snippet or any integration behavior.

## Testing

- `just test-ci` green: the smoke test covers `examples/app.py` to 100% (no
  exclusion) and calls the real task, asserting real behavior (not a mock).
- `just lint-ci` green (ruff/ty/eof/format over the new files).
- `just check-planning` green (this bundle validates).

## Risk

- **Example rot** (low x low) — mitigated structurally: the example is
  measured (no coverage exclusion) and the smoke test executes it every CI
  run, so a broken or uncovered example fails the build.
- **Example drifts from the README snippet** (low x low) — they share one
  shape; keep the example the runnable superset of the snippet.
