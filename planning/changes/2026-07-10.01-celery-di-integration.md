# Design: modern-di integration for Celery

**Status:** design, pending maintainer approval
**Target:** new repo `modern-python/modern-di-celery`, package `modern_di_celery`

## Summary

Ship the official [modern-di](https://modern-di.modern-python.org) integration
for [Celery](https://docs.celeryq.dev) **5.x**, following the core repo's
[Writing an integration](../../../modern-di/docs/integrations/writing-integrations.md)
contract along the **decorator path** (a Celery task is a plain callable with no
`Depends`-style seam, so this mirrors `modern-di-typer`), fully **synchronous**
(`close_sync`). One module (`modern_di_celery/main.py`) exposes `setup_di`,
`fetch_di_container`, `FromDI`, `inject`, and a `DITask` base class. A per-task
`Scope.REQUEST` child container is built and torn down by `inject`; the root
container's lifecycle rides Celery's worker-process signals.

## Motivation

Celery is the dominant Python task queue — a larger install base than taskiq —
and the roadmap's top "Next up" integration. It extends "one wiring, every
entrypoint" to the huge **synchronous** Celery worker crowd that the async
taskiq integration doesn't serve. Dishka has a Celery integration; modern-di has
none.

## Verified facts (Celery 5.6.3 + modern-di 2.27, spiked end-to-end)

Every non-obvious decision below was proven against installed Celery, not inferred:

- **`inject`'s signature rewrite makes Celery bind only real args.** A task
  decorated `@app.task`/`@inject` whose signature has the `FromDI` params
  stripped (via a set `__signature__`, **no `functools.wraps`** so no
  `__wrapped__`) is invoked with only the caller's real args — `explicit_task.delay(7).get()`
  injected the app- and request-scoped deps while the caller passed only `x=7`.
  (Unlike aiogram, Celery reads `__signature__` directly — no `inspect.unwrap`
  trap — but avoiding `functools.wraps` keeps it robust and matches the siblings.)
- **`DITask(Task)` auto-injects without a decorator.** Its `__init__` wraps
  `self.run` with `inject` and resets `self.__header__ = head_from_fun(injected)`
  so Celery's arg-spec reflects the stripped signature. `@app.task(base=DITask)`
  (or `Celery(task_cls=DITask)`) then injects every task. Verified:
  `ditask_task.delay(9).get()` injected while the caller passed only `y=9`.
- **`app.conf` is a mutable mapping** — the root-container store, read back with
  `current_app.conf[...]` inside `inject` (matching Dishka).
- **Worker-process signals** `worker_process_init` / `worker_process_shutdown`
  exist and fire `container.open` / `container.close_sync`. Verified by sending
  them manually (open→closed False, shutdown→closed True). Per-forked-process,
  the right granularity for Celery's prefork model.
- **Signal handlers must be connected `weak=False`.** Celery's `Signal.connect`
  defaults to weak references; a lambda/closure handler is garbage-collected
  before a worker process fires it (verified: a default-weak handler does **not**
  fire after `gc.collect()`; a `weak=False` named closure does). `container.open()`
  and `close_sync()` are idempotent (verified — a second call is a safe no-op),
  so the handlers accumulating across repeated `setup_di` calls (e.g. tests) is
  benign.
- **`task_always_eager = True` + `task_store_eager_result = True`** run tasks
  in-process via `.delay().get()` — the test harness, analogous to taskiq's
  `InMemoryBroker`.

## Design

### No connection provider

A Celery task carries no framework request object (like a Typer command), so
there is **no** connection `ContextProvider`. Unit of work: task → `Scope.REQUEST`.

### `setup_di(app, container) -> Container`

```python
def setup_di(app: Celery, container: Container) -> Container:
    app.conf[_ROOT_CONTAINER_KEY] = container

    def _open_container(**_: typing.Any) -> None:
        container.open()

    def _close_container(**_: typing.Any) -> None:
        container.close_sync()

    # weak=False is required — Celery signals default to weak refs, which would
    # garbage-collect these handlers before a worker process ever fires them.
    signals.worker_process_init.connect(_open_container, weak=False)
    signals.worker_process_shutdown.connect(_close_container, weak=False)
    return container
```

`worker_process_init` reopens the container in each forked worker process
(reopen-safe restart, matching every other integration); `worker_process_shutdown`
runs APP-scoped finalizers. `_ROOT_CONTAINER_KEY` is a named constant.

### `fetch_di_container(app) -> Container`

```python
def fetch_di_container(app: Celery) -> Container:
    return typing.cast(Container, app.conf[_ROOT_CONTAINER_KEY])
```

### `FromDI` marker + `inject` decorator (signature rewrite)

```python
@dataclasses.dataclass(slots=True, frozen=True)
class _FromDI(typing.Generic[T_co]):
    dependency: providers.AbstractProvider[T_co] | type[T_co]

def FromDI(dependency: providers.AbstractProvider[T] | type[T]) -> T:  # noqa: N802
    return typing.cast(T, _FromDI(dependency))

def inject(func):
    di_params = _parse_inject_params(func)          # name -> _FromDI
    if not di_params:                                # nothing to inject
        func.__modern_di_injected__ = True
        return func
    signature = inspect.signature(func)
    visible = [p for n, p in signature.parameters.items() if n not in di_params]

    def wrapper(*args, **kwargs):
        container = fetch_di_container(current_app).build_child_container(scope=Scope.REQUEST)
        try:
            resolved = {n: container.resolve_dependency(m.dependency) for n, m in di_params.items()}
            return func(*args, **kwargs, **resolved)
        finally:
            container.close_sync()

    wrapper.__name__ = func.__name__; wrapper.__qualname__ = func.__qualname__
    wrapper.__doc__ = func.__doc__; wrapper.__module__ = func.__module__
    wrapper.__signature__ = signature.replace(parameters=visible)   # NOT functools.wraps
    wrapper.__modern_di_injected__ = True
    return wrapper
```

`inject` reads the root off `current_app` (Celery's active-app proxy) at call
time — so a task decorated `@inject` needs no captured app. `resolve_dependency`
dispatches provider-vs-type (inherits overrides/caching/suggestions). Sync
throughout; the child is closed `close_sync` in `finally` (incl. the task error
path). The parse/rewrite helpers mirror `modern-di-typer`/`-aiohttp`.

Usage: `@app.task` **outside**, `@inject` **inside**, then task params marked
`svc: Annotated[Svc, FromDI(...)]`.

### `DITask(Task)` — the auto-inject path

```python
class DITask(Task):
    def __init__(self) -> None:
        super().__init__()
        if not getattr(self.run, "__modern_di_injected__", False):
            injected = inject(self.run)
            self.run = injected
            self.__header__ = head_from_fun(injected)
```

`Celery(task_cls=DITask)` or `@app.task(base=DITask)` injects every task without
a per-task `@inject`; the `head_from_fun` reset makes Celery bind only the real
args. This *is* the auto-inject mechanism (no separate flag).

### Public API (`__all__`)

`setup_di`, `fetch_di_container`, `FromDI`, `inject`, `DITask`.

## Non-goals

- **Async resolution** — resolution stays sync (`close_sync`); Celery workers
  are synchronous, a perfect fit.
- **A connection `ContextProvider`** — a task has no framework object to inject.
- **Celery signals beyond worker-process lifecycle** (task_prerun/postrun,
  result hooks) — the `inject`/`DITask` seam covers the per-task scope.
- **Celery 4.x** — 5.x only.
- Any runtime dependency beyond `celery` and `modern-di`; a separate docs site.

## Testing

`task_always_eager` + `task_store_eager_result`, 100%-coverage gate
(`just test-ci`), mirroring the sibling suites:

- `dependencies.py` — a `Group` with app- and request-scoped `Factory`
  providers (no connection object to read — Celery has none).
- `test_inject.py` — an `@app.task`/`@inject` task resolves app- and
  request-scoped values while the caller passes only the real args; the two
  request instances are distinct (uncached `Factory`); a no-`FromDI` task is a
  passthrough.
- `test_ditask.py` — the same via `@app.task(base=DITask)` with no `@inject`.
- `test_lifespan.py` — sending `worker_process_init` opens the root and
  `worker_process_shutdown` closes it; a second cycle re-opens without
  `ContainerClosedError`; `fetch_di_container` returns the same instance.
  (Eager mode does not spawn worker processes, so the tests **send the signals
  directly** — documented.)
- Error-path teardown — a task that raises; assert the per-task child was still
  closed (a REQUEST provider finalizer ran).

## Risk

- **R1 — Celery API drift.** `app.conf` mapping, `head_from_fun`, the
  `worker_process_*` signals, and `current_app` are relied on. *Mitigation:*
  pin `celery>=5,<6` (ruled by maintainer). The implementation step installs the
  `5.0` floor and runs the suite to confirm those APIs exist at the low bound;
  if one landed later in 5.x, raise the floor to the lowest green version and
  report it. The eager integration tests are the ongoing regression gate.
- **R2 — signature-rewrite / arg-binding.** If the rewrite regressed, Celery
  would require the DI params from the caller (or pass them wrong). Locked in and
  guarded by the resolution tests, which fail loudly if a DI param leaks into the
  bound arg-spec. Proven for both the `@inject` and `DITask` paths.
- **R3 — eager mode vs signals.** `worker_process_*` signals do not fire under
  `task_always_eager`; the lifespan tests send them directly. This tests the
  wiring, not Celery's own dispatch — acceptable (the connect call is the unit
  under test).
